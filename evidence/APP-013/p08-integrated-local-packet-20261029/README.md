# P08 local access/authentication sequence proof

Approved local-only preparation for R1-W01 / APP-013 / 3A / P08. `source/packet.py` is disabled at its native entry and has no credential, Cloud, database, Firebase, Stripe, or network transport. It accepts only injected ports and a synthetic exact plan. The source manifest locks the previously tested role, restoration, Stage A, key, and authentication seams.

The model proves the required order and refusal: two exact active role definitions; two intended bindings and ownership readbacks; all four Stage A results equal `CAN_ACCESS`; conditional API Keys readiness; absent-key check; one restricted, owned key; authentication callback while the key is owned; then independent key/binding/account/runtime cleanup. Its journal stores hashes and fixed status, never the key string, token, raw provider response, or database password. Unknown mutation outcomes remain residual and never trigger an automatic retry. An initially disabled API Keys service remains an explicit retention decision, even when the synthetic sequence otherwise succeeds.

The injected ports are **not** native adapters. This proof does not establish that current live IAM access is repaired, that API Keys can be enabled or a key created, that the disabled operator can authenticate, or that a payment is ready. Before any real operation, complete exact native transport and ownership/readback binding, a service-retention/cost decision, a fresh current-state preflight, an exact reviewed operation, and separate owner approval. R10 stays consumed; 3A remains open.

Validation: 13 local packet tests; unchanged role 26, Stage A 24, key 40, restoration 31, authentication 60 tests; backend architecture check. The key suite was run from its own working directory and the authentication suite from a no-space private scratch copy because their unchanged subprocess/file-URL harnesses fail when invoked from the checkout path containing `Web Projects`. No provider call was made during these tests.
